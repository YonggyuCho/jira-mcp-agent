# 웹 화면

에이전트의 실행 결과를 브라우저로 보고, 버튼으로 미리보기·발송을 하는 화면.
사용자가 "다시 보내봐", "리스트 뽑아줘", "보낸 거야?" 를 Claude 에게 매번 묻지 않아도 되게 하려고 만들었다.

조직 특정 값(도메인, IP, 누가 쓰는지)은 `docs/internal/WORKING-RULES.md` 6장과 `HANDOFF.md` 에 있다.
설치 절차는 `DEPLOYMENT.md` 의 "웹 화면" 절.

---

## 1. 구조

```
cron (평일 09:00) ─┐
                   ├─▶ python -m agent.daily ─▶ runs/<날짜>/<시각>-<출처>.json ─▶ Teams 웹훅
웹 버튼 ───────────┘           (판정)                  (실행 기록)
                                                          │
브라우저 ─ HTTPS ─▶ nginx :443 ─▶ 127.0.0.1:8090  web.server ─ 읽어서 표시
```

| 파일 | 역할 |
|---|---|
| `agent/store.py` | 실행마다 결과를 JSON 으로 저장. 성공·실패 모두. 웹·이력·"이전 대비" 의 원천 |
| `agent/daily.py` | `--trigger cron/web/manual` 로 출처를 남긴다. 기록 저장 실패는 종료 코드에 영향 없음 |
| `web/server.py` | 화면. **표준 라이브러리만** 쓴다 (서버 이전 시 설치할 것을 늘리지 않으려고) |
| `runs/` | 실행 기록. 이슈 키·담당자 이름이 있어 **`.gitignore` 로 제외** |

### 깨면 안 되는 것

1. **웹은 판정하지 않는다.** 버튼은 cron 과 똑같은 `python -m agent.daily` 를 subprocess 로 실행한다.
   그래서 웹에서 본 결과와 아침 리포트가 항상 같다. 판정 규칙은 `agent/collect.py` `_judge()` 한 곳.
2. **미리보기는 절대 보내지 않는다.** `AGENT_DRY_RUN=1` 을 강제로 넣어 실행한다.
3. **앱은 `127.0.0.1` 에만 묶는다.** 밖에서 직접 못 붙는다. HTTPS 는 nginx 가 맡는다.
4. **버튼(POST)은 같은 출처만 받는다** (CSRF 방지). 처리 후 303 으로 결과 화면에 보낸다 —
   새로고침해도 다시 발송되지 않게.
5. 발송·미리보기는 동시에 하나만 (잠금).

## 2. 화면

| 경로 | 내용 |
|---|---|
| `/` | 가장 최근 결과. 건수(위험·불일치·정상·전체), **이전 날짜 리포트 대비** 새로 걸림/해결, 버튼 2개, 표 |
| `/runs` | 실행 기록 — 자동·웹·수동, 성공·실패, 웹훅 응답, 오류 메시지 |
| `/run/<날짜>/<파일>` | 특정 실행 하나 |
| `/healthz` | 살아 있는지 (`ok`) |
| `POST /action/preview` | Jira 새로 읽기, 발송 안 함 |
| `POST /action/send` | 실제 Teams 발송 (확인 창) |

### 표

열: **판정 · 상위 (Epic) · 키 · 제목 · 유형 · 상태 · 담당 · 기한 · 일정 준수 · 이유**

- **상위 (Epic)**: 바로 위 이슈의 **제목만**(키 없이). 에픽 직속 이슈는 에픽 제목. 머리글만 보라색.
- **제목은 굵게** — 가장 중요한 열.
- 색: 🔴 위험 = 빨강, 🟠 불일치 = 주황, ✅ 정상 = 초록. 이유 글자도 같은 색.
- **엑셀식**: 머리글 클릭 = 정렬(▲▼). 머리글 아래 = 열별 필터 —
  값 열(판정·상위·유형·상태·담당·일정 준수)은 **체크박스 다중 선택**, 키·제목·이유는 글자 포함.
  상단 전체 검색, "보이는 건수 / 전체".
- 🆕 = 이전 리포트에는 없던 걸림.

### 주의

- **웹훅 202 는 Teams 가 받았다는 뜻일 뿐**이다. 채팅 게시 성공·실패는 Power Automate 실행 기록에만 남는다.
  실행 기록 화면의 "발송" 이 곧 "도착" 은 아니다.
- 상위 제목(`parent_title`)은 2026-10-08 이후 기록에만 있다. 그 전 기록은 "-".

## 3. 운영

```bash
systemctl status gpu-live-web            # 상태
sudo systemctl restart gpu-live-web      # web/server.py 를 고쳤으면 반드시
journalctl -u gpu-live-web -n 50         # 앱 로그 (접근 로그는 nginx)
sudo tail -f /var/log/nginx/access.log   # 접근 로그
sudo nginx -t && sudo systemctl reload nginx   # nginx 설정을 고쳤으면
sudo certbot certificates                # 인증서 만료일
systemctl list-timers certbot.timer      # 자동 갱신 타이머
ls runs/$(date +%F)/                     # 오늘 실행 기록
```

- **agent 쪽(판정·렌더)만 고쳤으면 웹 재시작은 필요 없다.** 버튼이 매번 새 프로세스로 agent 를 실행하고,
  화면은 저장된 JSON 을 읽기 때문이다. 다만 화면에는 **다음 실행부터** 새 규칙이 반영된다 — 바로 보려면 미리보기.
- `web/server.py`·`agent/store.py` 를 고쳤으면 재시작한다 (store 는 웹이 import 한다).
- 화면을 고친 뒤에는 `curl -s https://<도메인>/ | grep ...` 으로 HTML 이 바뀌었는지 본다.
  **서버에는 브라우저가 없어 클릭·모양 확인은 못 한다** — 사용자 스크린샷으로 확인한다.

### 접근 통제

앱에는 **로그인이 없다.** 접근 통제는 클라우드 보안 그룹(또는 nginx `auth_basic`)으로 한다.
**둘 다 없이 열면 누구나 발송 버튼을 누를 수 있다.**

로그인을 다시 붙이려면 `DEPLOYMENT.md` 의 "웹 화면" 절 — curl 로 확인할 때 `-w %{redirect_url}` 을
쓰면 비밀번호가 출력되는 함정이 있다.
