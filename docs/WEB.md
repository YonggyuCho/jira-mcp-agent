# 웹 화면

에이전트의 실행 결과를 브라우저로 보고, 버튼으로 미리보기·발송을 하는 화면.
사용자가 "다시 보내봐", "리스트 뽑아줘", "보낸 거야?" 를 Claude 에게 매번 묻지 않아도 되게 하려고 만들었다.

조직 특정 값(도메인, IP, 누가 쓰는지)은 `docs/internal/WORKING-RULES.md` 6장과 `HANDOFF.md` 에 있다.
설치 절차는 `DEPLOYMENT.md` 의 "웹 화면" 절.

---

## 1. 구조

```
cron (평일 09:00) ─┐
                   ├─▶ python -m agent.daily ─▶ runs/<날짜>/<시각>-<출처>.json ─▶ Teams 웹훅
웹 버튼 ───────────┘           (판정)                  (실행 기록)
                                                          │
브라우저 ─ HTTPS ─▶ nginx :443 ─▶ 127.0.0.1:8090  web.server ─ 읽어서 표시
```

| 파일 | 역할 |
|---|---|
| `agent/store.py` | 실행마다 결과를 JSON 으로 저장. 성공·실패 모두. 웹·이력·"이전 대비" 의 원천 |
| `agent/daily.py` | `--trigger cron/web/manual` 로 출처를 남긴다. 기록 저장 실패는 종료 코드에 영향 없음 |
| `web/server.py` | 화면 서버 (v2). **표준 라이브러리만** 쓴다. 판정 결과를 JSON 으로 만들어 템플릿에 넣는다 |
| `web/templates/app.html` | **화면 모양 전부** — Claude 디자인 목업을 옮긴 것. CSS·JS 인라인, 외부 리소스 없음. 서버는 `/*__DATA__*/null` 자리에 JSON 만 넣는다 |
| `web/server_v1.py` | **백업** — 디자인 개편 전 화면 (서버가 HTML 을 직접 만들던 판) |
| `web/__main__.py` | `python -m web` — `.env` 의 `WEB_UI` 로 판을 고른다. 기본 v2, `WEB_UI=v1` 이면 백업 |
| `runs/` | 실행 기록. 이슈 키·담당자 이름이 있어 **`.gitignore` 로 제외** |

### 깨면 안 되는 것

1. **웹은 판정하지 않는다.** 버튼은 cron 과 똑같은 `python -m agent.daily` 를 subprocess 로 실행한다.
   그래서 웹에서 본 결과와 아침 리포트가 항상 같다. 판정 규칙은 `agent/collect.py` `_judge()` 한 곳.
2. **미리보기는 절대 보내지 않는다.** `AGENT_DRY_RUN=1` 을 강제로 넣어 실행한다.
3. **앱은 `127.0.0.1` 에만 묶는다.** 밖에서 직접 못 붙는다. HTTPS 는 nginx 가 맡는다.
4. **버튼(POST)은 같은 출처만 받는다** (CSRF 방지). 처리 후 303 으로 결과 화면에 보낸다 —
   새로고침해도 다시 발송되지 않게.
5. 발송·미리보기는 동시에 하나만 (잠금).

## 2. 화면

| 경로 | 내용 |
|---|---|
| `/` | 가장 최근 결과. 건수(위험·불일치·정상·전체), **이전 날짜 리포트 대비** 새로 걸림/해결, 버튼 2개, 표 |
| `/runs` | 실행 기록 — 자동·웹·수동, 성공·실패, 웹훅 응답, 오류 메시지 |
| `/run/<날짜>/<파일>` | 특정 실행 하나 |
| `/create` | **Jira 등록 (데모)** — 상위 선택 + 매번 바뀌는 값만 입력, 고정값은 자동. 보낼 JSON 미리보기. **실제 등록은 안 함** |
| `/create?refresh=1` | 등록 양식을 Jira 에서 다시 읽기 (평소 10분 캐시) |
| `/healthz` | 살아 있는지 (`ok`) |
| `POST /action/preview` | Jira 새로 읽기, 발송 안 함 |
| `POST /action/send` | 실제 Teams 발송 (확인 창) |

### 표

열: **판정 · Epic · 프로젝트 · 키 · 제목 · 유형 · 상태 · 담당 · 기한 · 일정 준수 · 이유**

- **Epic / 프로젝트 (계층 2단)**: 이슈마다 위로 올라가 Epic 제목과 그 바로 아래 프로젝트·구축 제목을 따로 적는다
  (키 없이 제목만). 프로젝트·구축 이슈 자신은 프로젝트 칸에 자기 제목. Epic 은 보라 글씨, 프로젝트는 짙은 초록 글씨, 묶기는 **프로젝트별**.
  계산은 `agent/collect.py` 의 `lineage`. 예전 기록(필드 없음)은 바로 위 제목을 프로젝트로 본다.
- **제목은 굵게** — 가장 중요한 열.
- 색: 🔴 위험 = 빨강, 🟠 불일치 = 주황, ✅ 정상 = 초록. 이유 글자도 같은 색.
- **엑셀식**: 머리글 클릭 = 정렬(▲▼). 머리글 아래 = 열별 필터 —
  값 열(판정·상위·유형·상태·담당·일정 준수)은 **체크박스 다중 선택**, 키·제목·이유는 글자 포함.
  상단 전체 검색, "보이는 건수 / 전체".
- 🆕 = 이전 리포트에는 없던 걸림.

### 주의

- **웹훅 202 는 Teams 가 받았다는 뜻일 뿐**이다. 채팅 게시 성공·실패는 Power Automate 실행 기록에만 남는다.
  실행 기록 화면의 "발송" 이 곧 "도착" 은 아니다.
- 상위 제목(`parent_title`)은 2026-10-08 이후 기록에만 있다. 그 전 기록은 "-".

### 화면 판 바꾸기 (되돌리기)

사용자가 "예전 화면으로" 라고 하면 **Claude 가 직접** 한다 (사용자 지시).

```bash
echo 'WEB_UI=v1' >> /opt/jira-mcp/.env && sudo systemctl restart gpu-live-web   # 예전 화면
sed -i '/^WEB_UI=/d' /opt/jira-mcp/.env && sudo systemctl restart gpu-live-web  # 새 화면
```

디자인만 바꿀 때는 `web/templates/app.html` 만 고친다. 데이터 모양(`DATA.report.rows[]` 등)은
`web/server.py` 의 `_report()` 가 정한다 — 템플릿과 같이 맞춘다.

### Jira 등록 (데모) — `/create`

목적: Jira 화면에 매번 들어가 필드를 다 채우지 않고, **상위(Epic)만 고르고 매번 바뀌는 값만** 넣어 등록.
지금은 **데모** — 보낼 JSON 을 보여 줄 뿐 Jira 로 보내지 않는다. 토큰도 읽기 전용이다.

`web/jira_form.py` 가 Jira 를 실측해 양식을 만든다 (10분 캐시):
- 유형 id 는 `createmeta` 로 찾는다. 이 사이트는 '회의' 유형이 둘(일반·하위)이라 **하위(subtask) 쪽**을 고른다.
- 상위 후보 = 에픽(`AGENT_EPIC`) 직속 프로젝트·구축. 고르면 기본 유형(프로젝트→하위 작업, 구축→기술지원)·권역·고객사명·요청 경로가 따라온다.
- 사람 목록 = 대상 이슈에 담당·보고·엔지니어·참조로 나온 사람, 많이 나온 순. 엔지니어 기본값 = 가장 흔한 조합.
- 고정값 = 실측에서 100% 같은 값(솔루션·지원 방법·우선순위), 이슈 분류는 판정 규칙과 같은 규칙으로 자동.

| 구분 | 필드 |
|---|---|
| 입력 | **등록 방식**(등록만 / 진행 중까지 / 종료까지 — 기본), 유형, 제목, 담당자, 요청 경로, 시작(날짜+시각 → 시작 날짜·Actual start 둘 다), 기한, 엔지니어(회의는 참조), 설명 |
| 입력 (종료까지) | 종료(Actual end, 날짜+시각), 일정 준수 여부(종료일·기한으로 자동 추천, 사람이 바꾸면 그 값 유지), Delayed 면 지연 사유 |
| 고정·자동 | 프로젝트, 상위, 솔루션, 엔지니어 지원 방법, 고객사명(통합키), 권역, 우선순위, 이슈 분류, 보고자(=토큰 계정) |

미리보기는 등록 방식에 따라 **보낼 요청을 단계별로**(1 등록 → 2 진행 중 → 3 종료 → 4 실제 값 다시 넣기) 보여 준다.

"등록 전 검사" 는 매일 리포트의 미기입 규칙과 같은 항목을 본다 — 이 화면으로 만든 이슈는 리포트에 안 걸리게.

**등록 + 진행 중 + 종료를 한 번에 (실측 결과, 2026-10-08):** 가능하다. 단 순서가 중요하다 —
전환이 Actual start/end 를 '지금 시각' 으로 덮어쓰므로 실제 날짜는 **마지막에** 넣는다 (`JIRA-FIELDS.md` 7장).

```
1. POST /issue                    등록 (상태 = 미해결)
2. POST /issue/<키>/transitions   {"transition":{"id":"2"}}  작업 시작 → 진행 중  (Actual start = 지금 으로 덮임)
3. POST /issue/<키>/transitions   {"transition":{"id":"3"}}  종결 → 종료         (Actual end = 지금 으로 덮임)
4. PUT  /issue/<키>               Actual start / Actual end / 일정 준수 여부 를 실제 값으로
```

중간에 실패하면 이슈는 이미 만들어진 상태라, 화면에 키와 어디까지 됐는지를 보여 줘야 한다.

**실제 등록을 켜려면 (다음 단계):** ① 토큰에 `write:jira-work` 범위 ② 서버에 `POST /action/create` 를 추가해
`POST /rest/api/3/issue` 로 보낸다 (페이로드는 화면의 JSON 그대로) ③ 프로젝트·유형 화이트리스트와 확인 창
④ 실행 기록에 남기기. 쓰기는 되돌리기 어려우니 켜기 전에 사용자 확인.

## 3. 운영

```bash
systemctl status gpu-live-web            # 상태
sudo systemctl restart gpu-live-web      # web/server.py 를 고쳤으면 반드시
journalctl -u gpu-live-web -n 50         # 앱 로그 (접근 로그는 nginx)
sudo tail -f /var/log/nginx/access.log   # 접근 로그
sudo nginx -t && sudo systemctl reload nginx   # nginx 설정을 고쳤으면
sudo certbot certificates                # 인증서 만료일
systemctl list-timers certbot.timer      # 자동 갱신 타이머
ls runs/$(date +%F)/                     # 오늘 실행 기록
```

- **agent 쪽(판정·렌더)만 고쳤으면 웹 재시작은 필요 없다.** 버튼이 매번 새 프로세스로 agent 를 실행하고,
  화면은 저장된 JSON 을 읽기 때문이다. 다만 화면에는 **다음 실행부터** 새 규칙이 반영된다 — 바로 보려면 미리보기.
- `web/server.py`·`agent/store.py` 를 고쳤으면 재시작한다 (store 는 웹이 import 한다). `app.html` 은 요청마다 읽으므로 재시작 없이 반영된다.
- 화면을 고친 뒤에는 `curl -s https://<도메인>/ | grep ...` 으로 HTML 이 바뀌었는지 본다.
  **서버에는 브라우저가 없어 클릭·모양 확인은 못 한다** — 사용자 스크린샷으로 확인한다.

### 접근 통제

앱에는 **로그인이 없다.** 접근 통제는 클라우드 보안 그룹(또는 nginx `auth_basic`)으로 한다.
**둘 다 없이 열면 누구나 발송 버튼을 누를 수 있다.**

로그인을 다시 붙이려면 `DEPLOYMENT.md` 의 "웹 화면" 절 — curl 로 확인할 때 `-w %{redirect_url}` 을
쓰면 비밀번호가 출력되는 함정이 있다.
